# 整合与验收：每次只接一个已完成模块

[模块目录](README.md) · [上一章](15-oled-clock.md)

## 设计思想

单模块验收通过后才连接调用者。最终工程使用当前“一个页面一个源文件”的结构，旧教程的大 `app.c`快照仅作历史练习，不与新模块同时编译。整合先验证启动与返回链，再验证业务边界，最后上板确认硬件表现。

## A 移植：建立编译与接口清单

| 分组 | 需要注册的源文件 | 头文件/依赖 |
|---|---|---|
| 工具生成 | main/gpio/i2c/tim/rtc、IRQ、系统及HAL/CMSIS/启动文件 | CubeMX当前工程 |
| 显示与数据 | `OLED.c`、`OLED_Data.c` | `OLED.h`、`OLED_Data.h`、`OLED_HAL_Config.h`、`watch_config.h` |
| 按键 | `key.c` | `key.h` |
| 应用/首页/设置/菜单 | `app.c`、`home_page.c`、`settings_page.c`、`menu_page.c` | 各自同名 `.h` |
| 子页面 | `stopwatch_page.c`、`game_page.c`、`animation_page.c`、`oled_test_page.c` | 各自同名 `.h` |
| 游戏规则 | `game.c` | `game.h`与位图声明 |

1. `.c`必须加入Keil编译列表，`.h`所在目录必须加入Include Paths；二者作用不同。
2. 每个函数只有一份实现，替换临时空壳后不再保留旧文件里的同名函数。
3. 使用UTF-8 BOM保存含中文源码，包含路径和预处理宏与模块01一致。
4. 教程 [reference](reference/README.md)是对照快照，不整体加入Keil。运行的是外层 `bsp/Core`，不要把两份源码同时编译。

## B 自己编码：接线顺序

### 第1步：确认完整启动链

```text
HAL_Init → 时钟 → GPIO → RTC → TIM2 → I2C1 → App_Init
main while(1) → App_Run → HomePage_Run → 入口号 → 菜单或设置
```

`App_Init`只调用一次；中断链是 `TIM2_IRQHandler → HAL_TIM_IRQHandler → HAL_TIM_PeriodElapsedCallback → KEY_Scan`。SysTick调用 `HAL_IncTick`，为游戏、动画、秒表提供HAL毫秒时基。

### 第2步：只连接首页与设置

用断点确认首页返回1/2，设置返回时没有重新初始化外设。先完成两屏浏览和字段加减，再看RTC覆盖编辑值的现象，不把当前未写回误判成按键丢失。

### 第3步：逐项连接菜单

先0返回与2输出，再1秒表、4游戏、5动画、6测试。每次子页退出后菜单恢复全屏；3保持占位。保留菜单选择，不在子页返回后硬设0。

### 第4步：检查状态生命周期

| 状态 | 退出后再次进入 | 重新上电 |
|---|---|---|
| 首页选择 | 保留 | 初始1 |
| 设置选择 | 重置到Back | 初始Back |
| 菜单选择 | 保留 | 初始0 |
| 秒表时间/运行标志 | 保留，但离开期间不累计 | 清零/停止 |
| 游戏本局 | 新一局 | 新一局 |
| 游戏最高分 | 保留RAM值 | 清零 |
| 动画播放帧 | 从第0帧开始 | 从第0帧开始 |
| OLED测试参数 | 当前上电继续使用 | 回到宏设置 |

### 第5步：运行现有主机检查

在含 `bsp/Core/tests`的完整工程根目录执行；克隆本仓库后先进入 [firmware目录](../../firmware/README.md)，需PATH里有GCC：

```powershell
./tests/run_game_tests.ps1
./tests/run_page_tests.ps1
```

前者包括游戏逻辑和模拟显存对照；后者包括9组页面交互：

| 场景 | 检查内容 |
|---|---|
| 0 | 首页双向切换、菜单返回 |
| 1 | 六字段编辑与返回 |
| 2 | 秒表运行后退出/重新进入保留状态 |
| 3 | PB15切换调用 |
| 4 | KUN动画与返回 |
| 5 | OLED时钟档位成功路径 |
| 6 | 游戏进入、更新、跳跃、返回 |
| 7 | 菜单3占位 |
| 8 | 秒表暂停和清零 |

测试成功说明当前行为可重复，并不表示已修好现有边界缺陷。按键真实消抖、RTC实际读写、I2C故障/通信、板上计时误差和拍摄闪烁不由这些主机替身保证。参考快照没有完整素材/测试依赖，不能在 `reference`目录直接运行这些命令。

## 板上验收顺序

1. 启动能到首页，时间递增，三个键松手各只产生一个事件。
2. 首页、设置、菜单和全部已接子页能往返，无递归进入菜单造成的栈增长。
3. 菜单滑动不残影，PB15动作与实物电平一致。
4. 秒表开始/暂停/清零/重进符合上表；记录当前秒级精度限制。
5. 游戏边界/重生/跳跃顶部无残影，暂停恢复不补算暂停时间。
6. 动画回绕正常，测试页保持静态；拍摄参数与观察结果单独记录。
7. 设置0减1、时23继续加、2月日期、RTC复位分别记录为当前已知缺陷，后续改进单独验收，不在当前教程中伪称完成。

后续功能依次做：字段/日期合法性 → RTC确认写回 → 初始化标记与日期恢复 → 更精确秒表 → 非阻塞菜单/事件队列 → 未接传感器与电源功能。每次先补需求、变量和状态图，再编码并增加有实际意义的验证。
