# 10 PB15输出：先做最小输入到输出闭环

[模块目录](README.md) · [上一章](09-menu.md) · [下一章](11-stopwatch.md)

## 设计思想

这是最小应用：菜单选中编号2后，确认事件使输出电平翻转一次。GPIO输出锁存器已经保存高/低状态，当前无需再维护一份软件布尔量。它也验证了“驱动只产生事件，页面决定意义”的分层。

## 变量与逻辑

| 状态/输入 | 用途 |
|---|---|
| `menuFlag==2` | 限定只有本菜单项接收输出动作 |
| `key==3` | 已松手的确认事件 |
| PB15输出锁存值 | 当前高/低状态，上电初始化为低 |
| `WATCH_LED_ON_LEVEL` | 预留宏，当前菜单没有引用 |

```text
初始化PB15为低 → 选择菜单2 → 按下松开键3 → 低变高
再次确认 → 高变低 → 退出菜单不会自动恢复
```

## A 移植：只接HAL GPIO与实际电路

1. 在CubeMX设PB15推挽输出，初始低，对照 [gpio.c](reference/Core/Src/gpio.c)。
2. 如果接的是LED或外部开关，按实际电路确定哪个电平有效；“输出高”不必然等于“灯亮”。当前代码只证明翻转电平，不能凭宏声称手电筒功能完整。
3. 不复制原标准库 `GPIO_SetBits/ResetBits`，使用HAL接口。这个功能没有独立 `.c`，保持在菜单确认分支中即可。

## B 自己编码：把动作放进确认分支

### 第1步：先确认初始状态

GPIO初始化中应先设置输出值，再设置输出模式；当前生成代码为：

```c
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_15, GPIO_PIN_RESET);
```

此语句由CubeMX生成，不在菜单循环中重复初始化。

### 第2步：只在菜单2确认时翻转

```c
/* MenuPage_Run：key==3分支内 */
else if (menuFlag == 2) {
    HAL_GPIO_TogglePin(GPIOB, GPIO_PIN_15);
}
```

不能把它放到 `menuFlag==2`每轮都会执行的地方，否则没有按键也会不断翻转。

### 第3步：决定是否需要独立模块

当前只有一次HAL调用，不额外创建状态。以后若增加闪烁模式、进入/退出策略或电源锁存，再设计 `Output_Set/Output_Run`和状态变量，同时统一配置宏；当前固件尚未进行这一步。

## 验收与边界

用调试器或万用表确认每次松手仅翻转一次，按住不连跳，退出菜单保留输出。当前测试检查的是PB15调用次数，不证明外部负载亮度或供电效果；硬件表现由实物验收。
